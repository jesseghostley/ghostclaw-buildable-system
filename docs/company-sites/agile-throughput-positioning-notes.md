# Agile Throughput Positioning Notes

## Core category shift

Do not position Agile as an agency that always sells more traffic or more leads.

Position the system around contractor throughput:

> **We find and improve the bottleneck limiting profitable completed jobs.**

## Core message hierarchy

1. A contractor business grows only as fast as its current constraint allows.
2. More demand is useful only when demand is actually the constraint.
3. The Website Factory connects visibility, trust, lead capture, response, sales, proof, follow-up and capacity into one measurable operating system.
4. We diagnose before prescribing.
5. We exploit the current bottleneck before adding more load upstream.
6. We measure downstream business outcomes and re-diagnose when the constraint moves.

## Home-page direction

Potential hero direction:

**Find the bottleneck. Build the system around it.**

Supporting copy:

Agile builds AI-powered website and growth systems for contractors, but we do not assume more traffic is the answer. We measure the path from demand to completed job, identify the constraint limiting throughput, and improve that part of the system first.

Primary CTA:

**Find My Growth Constraint**

Secondary CTA:

**See How the System Works**

## Strong differentiator

Traditional agency framing:

`More traffic → more leads → hope operations absorb them`

Agile framing:

`Measure the business → find the bottleneck → improve it → increase profitable throughput → find the next bottleneck`

## Public examples

- Enough traffic but weak trust → add verified project proof and reviews before buying more traffic.
- Enough inquiries but slow response → fix routing and follow-up before scaling SEO/ads.
- Strong appointments but poor close rate → improve estimate/sales process before increasing lead volume.
- Demand already exceeds fulfillment capacity → improve capacity/process before increasing demand.

These examples should remain illustrative and should not imply client-specific measured results unless verified.
